# MLBB Stats API — подробный справочник

Для начала работы откройте [короткую инструкцию](./README.md). Здесь собраны дополнительные параметры, поля и ограничения.

API для серверных интеграций: авторизация игрока по коду из игры, профиль, общая статистика, сезоны и герои.

**Базовый адрес:** `https://mlbb-stats.ru/api/v1`  
**Версия:** v1, пилотный доступ по выданному ключу.  
**Документация проверена:** 19 октября 2026 года.

Это API проекта MLBB Stats, не официальный API Moonton. Доступ к API не означает доступ ко всей истории любого игрока. Ответы зависят от доступных данных, авторизации и Premium.

## Файлы

- [openapi.json](./openapi.json) — схема OpenAPI 3.0.3; можно импортировать в Postman или Swagger Editor.
- [examples.http](./examples.http) — запросы для HTTP-клиента IDE; ключи берутся из переменных окружения.
- [examples/profile.mjs](./examples/profile.mjs) — пример серверного запроса на Node.js 22+, без зависимостей.

Актуальная схема сервера: [GET /api/v1/openapi.json](https://mlbb-stats.ru/api/v1/openapi.json). Она доступна без ключа; для импорта по URL используйте полный HTTPS-адрес сервера, если инструмент не разрешает относительный `servers.url`.

## 1. Подключение

1. Получите ключ приложения у MLBB Stats: [partners@mlbb-stats.ru](mailto:partners@mlbb-stats.ru).
2. Сохраните его в переменной окружения **своего сервера** `MLBB_API_KEY`.
3. Вызывайте API со своего backend. Браузер вашего пользователя должен обращаться к вашему backend, а не напрямую с ключом к MLBB Stats.
4. Для входа игрока запросите его ID и сервер, отправьте код с его согласия и подтвердите код отдельным запросом.

Ключ нельзя включать в frontend, мобильный клиент, URL, публичный Git или логи. Не отправляйте пользователям сам ключ приложения. Прямой доступ с произвольного сайта через CORS не предусмотрен.

Во всех запросах, кроме схемы:

```http
X-API-Key: <ключ вашего приложения>
```

Для сессии игрока дополнительно:

```http
Authorization: Bearer <accessToken из auth/verify>
```

Это две разные сущности: ключ идентифицирует приложение, токен — вошедшего игрока. Токен действует только с приложением и ключом, для которых был получен. Токены входа на сайт не заменяют API-токен.

## 2. Все методы

Пути указаны относительно базового адреса.

| Метод | Путь | Что возвращает | Токен игрока |
| --- | --- | --- | --- |
| GET | `/openapi.json` | Схема API, ключ тоже не нужен | Не нужен |
| POST | `/auth/send-code` | Отправка кода, создание `challengeId` | Не нужен |
| POST | `/auth/verify` | Подтверждение кода, токен и профиль | Не нужен |
| GET | `/auth/me` | Свой профиль, Premium, срок сессии | Обязателен |
| POST | `/auth/logout` | Отзыв текущей API-сессии | Обязателен |
| GET | `/players/{playerKey}` | Кешированный профиль | Необязателен |
| GET | `/players/{playerKey}/stats` | Общие метрики | Необязателен |
| GET | `/players/{playerKey}/seasons` | Сводки сезонов и доступность подробностей | Необязателен |
| GET | `/players/{playerKey}/seasons/{season}` | Метрики конкретного сезона | Для прошлого — владелец с Premium |
| GET | `/players/{playerKey}/heroes` | Статистика героев | Для прошлого сезона — владелец с Premium |
| GET | `/players/{playerKey}/heroes/{heroId}` | Статистика одного героя | Для прошлого сезона — владелец с Premium |

`playerKey` — строка `playerId-serverId`, например `12345678-1234`. Сервер обязателен: одинаковый ID на разных серверах не следует считать одним аккаунтом. Идентификаторы — положительные целые без пробелов, плюса, дробей и ведущих нулей. В примерах используются вымышленные ID и значения.

## 3. Вход по коду

### Отправка

```http
POST /api/v1/auth/send-code
X-API-Key: <ключ>
Content-Type: application/json

{"playerId":12345678,"serverId":1234}
```

Пример ответа `200`:

```json
{
  "data": {
    "challengeId": "00000000-0000-4000-8000-000000000001",
    "expiresIn": 300
  },
  "meta": { "requestId": "example-request-id" }
}
```

Код приходит в игру. Сохраните полученный `challengeId` на сервере в контексте входа пользователя. Запрос действует **5 минут**, допускается **до 3 попыток** проверки. Не отправляйте код автоматически при каждом открытии страницы.

### Подтверждение

```http
POST /api/v1/auth/verify
X-API-Key: <ключ>
Content-Type: application/json

{"challengeId":"<полученный challengeId>","code":"<код из игры>"}
```

`code` — строка из 4–16 латинских букв или цифр. Не преобразовывайте код в число: ведущие нули имеют значение. Повторно передавать `playerId` и `serverId` сюда не нужно и нельзя.

Ответ `200` содержит:

| Поле в `data` | Значение |
| --- | --- |
| `accessToken` | Токен игрока, хранить конфиденциально |
| `tokenType` | `Bearer` |
| `expiresIn` | `86400` секунд — 24 часа |
| `player` | Профиль в формате раздела «Поля» |

Успешно использованный `challengeId` нельзя применить повторно. Не сохраняйте игровой код и не выводите его в логи. После входа данные могут обновляться в фоне; успешный вход не гарантирует немедленную загрузку всей статистики.

### Сессия и выход

`GET /auth/me` с обоими заголовками возвращает профиль и дополнительные поля `isPremium`, `sessionExpiresAt` (ISO 8601).

`POST /auth/logout` с обоими заголовками, без тела или с `{}`, отзывает текущую API-сессию. Успех — **204 без JSON**. Удалите токен у себя; повторное использование отозванного токена возвращает `401`.

Refresh token отсутствует. После истечения сессии или при `meta.requiresReauth: true` предложите повторный вход через игру. Перевыпуск ключа приложения делает старый ключ и связанные с ним сессии недействительными. Отключение приложения закрывает доступ по его ключу.

## 4. Профиль, статистика и параметры

| Запрос | Допустимые query-параметры |
| --- | --- |
| `/players/{playerKey}` | `fields`, `include=stats` |
| `/players/{playerKey}/stats` | `fields`, `mode` |
| `/players/{playerKey}/seasons` | `fields`, `limit`, `offset` |
| `/players/{playerKey}/seasons/{season}` | `fields`, `mode` |
| `/players/{playerKey}/heroes` | `fields`, `mode`, `season`, `sort`, `limit`, `offset` |
| `/players/{playerKey}/heroes/{heroId}` | `fields`, `mode`, `season` |

Методы `/auth/*` не принимают query-параметры. Неизвестные query-параметры и дополнительные поля тела авторизации отклоняются. Не повторяйте один query-параметр несколько раз.

### Выбор полей

```text
/players/12345678-1234?fields=name,avatar,currentRank.stars
/players/12345678-1234?include=stats&fields=name,stats.games,stats.winRate
/players/12345678-1234/heroes?fields=heroId,nameRu,games,winRate&limit=3
```

`fields` — известные имена через запятую **без пробелов**. До 40 разных полей и до 1000 символов. Без параметра возвращается полный объект данного метода. Для вложенного ранга укажите `currentRank.stars`, а не `currentRank`; для статистики внутри профиля — `stats.games` и обязательно `include=stats`. Вложенность в ответе сохраняется.

Выбор полей уменьшает ответ вашему приложению, но не является отдельной квотой или обещанием более дешёвого получения данных.

### Режимы, сезоны и списки

- `mode`: `all` (по умолчанию), `ranked`, `classic`, `rising`.
- `all` — объединённая доступная статистика режимов, а не только рейтинг.
- `season`: положительный номер, не больше текущего сезона. На дату этой документации сервер настроен на **42-й сезон**; не зашивайте этот номер навсегда.
- `/stats` — общие метрики, **не принимает `season`**. Для сезона используйте `/seasons/{season}`.
- `heroes` без `season` — общая доступная статистика героев; с `season` — выбранного сезона.
- `sort` только у списка героев: `-games` (по умолчанию), `-winRate`, `heroId`. При равенстве — порядок по `heroId`.
- `limit`: 1–100, по умолчанию 50; `offset`: 0–10000, по умолчанию 0.
- У списков в `meta` есть `total`, `limit`, `offset`. Следующая страница: увеличьте `offset` на `limit`.
- В списке сезонов один сезон может встречаться несколько раз для разных режимов. Идентичность строки — пара `season` + `mode`; `total` считает строки, не уникальные сезоны.

## 5. Доступ и Premium

| Данные | Что требуется |
| --- | --- |
| Известный кешированный профиль, общая статистика и герои | Ключ приложения |
| Сводки сезонов | Ключ приложения; `accessible` показывает доступ к подробностям |
| Подробности текущего сезона | Ключ приложения, если данные доступны |
| Подробности прошлого сезона, включая героев | Ключ + API-токен **владельца этого аккаунта** + активный Premium владельца |
| `/auth/me`, `/auth/logout` | Ключ + API-токен |

Ключ приложения не даёт Premium и не открывает чужую закрытую историю. Premium другого игрока не помогает. Переданный просроченный или неправильный Bearer-токен приводит к `401`, даже если без Bearer данный метод допускает чтение по ключу.

Если игрок ещё неизвестен сервису, чтение может вернуть `404 player_not_found`. Вход с согласия владельца позволяет добавить его аккаунт. API не предоставляет массовый каталог всех пользователей.

## 6. Формат ответа и отсутствие данных

Успех, кроме logout:

```json
{
  "data": { "games": 120, "winRate": 55 },
  "meta": {
    "requestId": "example-request-id",
    "source": "cache",
    "stats": { "updatedAt": "2026-10-19T12:00:00.000Z", "stale": false },
    "available": true,
    "completeness": "aggregate_only",
    "detailStatsAvailable": false,
    "refreshQueued": false
  }
}
```

Пример выше — ответ с выбором `fields=games,winRate`. Набор `meta` зависит от метода.

| Поле `meta` | Смысл |
| --- | --- |
| `requestId` | Идентификатор запроса для обращения в поддержку; также заголовок `X-Request-ID` |
| `source` | Сейчас `cache`: ответ из доступных сохранённых данных |
| `profile.updatedAt`, `stats.updatedAt` | Дата обновления соответствующего кеша; может быть `null` |
| `profile.stale`, `stats.stale` | Данные старше порога свежести (сейчас 5 минут) либо дата неизвестна |
| `refreshQueued` | Обновление поставлено в очередь или уже идёт; не гарантия результата или срока |
| `requiresReauth` | Владельцу нужен повторный вход; поле доступно в контексте владельца |
| `available` | Доступны ли запрошенные данные статистики/героя |
| `detailStatsAvailable` | Есть ли подробные боевые показатели |
| `completeness` | `detailed`, `partial`, `aggregate_only` или `unavailable` |

`partial` означает неполный охват, `aggregate_only` — доступны агрегаты без полной боевой статистики. `detailed` не означает гарантированно всю историю аккаунта за всё время.

Если данных нет, отдельная статистика/герой могут быть `data: null`, списки — `data: []`. Недоступные числовые показатели возвращаются как `null`, не как выдуманный ноль. При отсутствии выбранного сезона или режима API не подставляет вместо них общую статистику.

Общие метрики могут опираться на агрегаты за всё время. Их нельзя надёжно восстановить простым суммированием полученных карточек сезонов.

## 7. Поля

### Профиль

`playerId`, `serverId`, `name`, `avatar`, `level`.

`currentRank` и `historyRank` содержат: `level`, `name`, `nameEn`, `subrank`, `stars`, `tier`. `level` внутри ранга — код ранга, а не уровень аккаунта. Точные типы и допустимость `null` смотрите в OpenAPI.

### Общие и сезонные метрики

| Поле | Значение |
| --- | --- |
| `games`, `wins` | Матчи и победы |
| `winRate` | Процент побед |
| `kills`, `deaths`, `assists` | Убийства, смерти, помощи |
| `kda` | Средний игровой показатель KDA |
| `kdaRatio` | Отношение сумм убийств и помощей к смертям; не обязательно равно `kda` |
| `mvp`, `mvpRate` | Число MVP и их процент |
| `avgDamage`, `avgDamageTaken` | Средний нанесённый и полученный урон |
| `avgGoldPerMinute` | Среднее золото в минуту |
| `teamfightParticipation` | Участие в командных боях, проценты |
| `battleTimeSeconds` | Время боёв в секундах |
| `heroesPlayed` | Количество героев в доступной статистике |

`winRate`, `mvpRate`, `teamfightParticipation` — проценты: `55.5` означает **55,5%**, не `0.555`. Подробные боевые показатели могут быть `null`.

### Герой

`heroId`, `name`, `nameRu`, `icon`, `games`, `wins`, `winRate`, `kills`, `deaths`, `assists`, `kda`, `kdaRatio`, `mvp`, `avgScore`, `avgDamage`, `avgDamageTaken`, `avgGoldPerMinute`, `teamfightParticipation`, `battleTimeSeconds`, `expert`.

`avgScore` — средняя оценка; `expert` — булев признак или `null`. Здесь нет полей `mvpRate` и `heroesPlayed`.

### Сводка сезона

`season`, `mode`, `games`, `winRate`, `kda`, `mvp`, `accessible`.

`accessible` относится к подробностям сезона для текущего запроса, а не гарантирует наличие данных. В агрегированной строке `mode: all` значения `kda` и `mvp` могут быть `null`.

## 8. Лимиты

| Ограничение | Максимум |
| --- | --- |
| Запросы одного приложения | 30 в минуту, 1000 за сутки UTC |
| Запросы одного IP | 60 в минуту, включая неверные ключи и чтение схемы |
| Одновременные запросы приложения | 2 |
| Отправка кода одному игроку | 3 за 15 минут; интервал минимум 60 секунд |
| Отправка кодов приложением | 10 за 15 минут |
| Проверка кода одному игроку | 5 за 15 минут |
| Проверки кодов приложением | 20 за 15 минут |
| Один `challengeId` | 5 минут, до 3 попыток |
| Тело JSON | До 4 КиБ; сжатие тела не поддерживается |

Дополнительно действуют общие ограничения сервиса, сайта и авторизации с одного IP. Поэтому запрос может получить ограничение раньше, чем исчерпан отдельный лимит из таблицы. Суточное окно UTC меняется в 00:00 UTC — это 03:00 по Москве.

Лимиты игрока общие для приложений. Повторный вход и перевыпуск ключа не обнуляют квоты. Запрос, принятый по ключу, может расходовать лимит даже при последующей ошибке параметров или авторизации; отклонённые попытки входа также могут расходовать бюджет.

При `429` учитывайте `Retry-After` в секундах. При временном `503` также учитывайте этот заголовок, если он есть; иначе используйте ограниченное число повторов с увеличивающейся задержкой. Не запускайте бесконечные повторы и не повторяйте автоматически POST отправки/проверки кода: результат предыдущего запроса мог быть потерян в сети.

Не опрашивайте все профили раз в секунду. Кешируйте ответы у себя, объединяйте одновременные запросы одного профиля и обновляйте по пользовательскому действию с учётом квот.

## 9. Ошибки

```json
{
  "error": { "code": "quota_exceeded" },
  "meta": { "requestId": "example-request-id" }
}
```

| HTTP | Примеры `error.code` | Что делать |
| --- | --- | --- |
| 400 | `invalid_player_id`, `invalid_parameter`, `invalid_mode`, `invalid_include`, `invalid_sort`, `invalid_fields`, `invalid_request`, `unknown_query_parameter`, `invalid_json`, `invalid_code_format`, `invalid_challenge` | Проверить формат и допустимые параметры |
| 401 | `invalid_api_key` | Проверить ключ, не был ли перевыпущен или отключён |
| 401 | `authorization_required`, `invalid_session`, `session_revoked` | Проверить сессию, при необходимости повторить вход |
| 401 | `invalid_code`, `challenge_expired_or_used` | Проверить введённый код; при исчерпании запроса начать новый вход с учётом лимитов |
| 403 | `past_season_owner_premium_required` | Нужны владелец аккаунта и его активный Premium |
| 404 | `player_not_found`, `endpoint_not_found` | Проверить ID, наличие аккаунта в сервисе или путь |
| 413 | `payload_too_large` | Уменьшить тело JSON |
| 415 | `unsupported_media_type` | Отправлять поддерживаемый несжатый JSON |
| 422 | `invalid_player` | Проверить аккаунт для отправки кода |
| 429 | `quota_exceeded`, `auth_rate_limited`, `ip_rate_limited`, `concurrent_request_limit`, `rate_limited` | Подождать согласно `Retry-After`, снизить нагрузку |
| 503 | `service_unavailable`, `auth_unavailable`, `developer_api_disabled` | Не повторять агрессивно; при длительной проблеме обратиться в поддержку |

Это основные коды, а не обещание неизменности всех ошибок инфраструктуры. При проблеме сети или прокси ответ может не быть JSON. Сохраняйте HTTP-статус и `requestId`, но не ключ, Bearer-токен и игровой код.

## 10. Пример Node.js

Установите на своём сервере переменные `MLBB_API_KEY` и `MLBB_PLAYER_KEY`, затем:

```sh
node examples/profile.mjs
```

Пример делает один GET, не отправляет код в игру и не выполняет автоматические повторы. При ошибке показывает только статус, код, requestId и Retry-After.

Для своей интеграции храните токен игрока на backend и связывайте его с сессией вашего пользователя. Не давайте посетителю произвольно подставлять чужой сохранённый токен. Не журналируйте заголовки авторизации и тела запросов входа.

## 11. Что пока не предоставляется

- История отдельных матчей.
- Гарантированная полная история всех сезонов и мгновенное обновление.
- Refresh token, webhooks и потоковые обновления.
- Обход Premium или получение закрытых данных чужого аккаунта.
- Публичная выдача ключей без согласования.

Вопросы по подключению и проблемам: [partners@mlbb-stats.ru](mailto:partners@mlbb-stats.ru). Для разбора ошибки приложите время, метод, путь без секретов, HTTP-статус и `requestId`.
